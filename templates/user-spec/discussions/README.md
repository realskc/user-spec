# 讨论

这里放作者和 agent **讨论时写下的东西**：一个问题复杂、口头讲不清，作者需要一份能反复看的讲解、例子或方案比较时，agent 就写一份讨论稿。讨论稿是记录，不是预期；怎么读见 [../README.md「讨论」](../README.md)。

## 什么时候写

只在讨论复杂、作者需要一份能反复看的东西时才写。短的讨论照旧在对话里进行。讨论中定下的、以后要做的事，要在 [TODO.md](../../TODO.md) 挂一条，指回讨论稿：讨论稿结束后不再有人回头看，只记在这里就会被忘掉。

## 放哪、怎么命名

- 文件名：`YYYY-MM-DD-简短英文标识.md`（讨论开始的日期），按时间排序。不另外编号：一次讨论可能产出好几条决策，一条决策也可能来自好几次讨论。
- 项目分成几个部分时，只关于某个部分的讨论放在那个部分的 `user-spec/discussions/`，写法相同。

## 开头写什么

```markdown
# 讨论：题目

- 日期：YYYY-MM-DD（讨论开始的日期）
- 参与：作者，和哪个 agent / 模型
- 状态：进行中 / 已结束
- 为什么写：为了讨论什么问题
- 结论去了哪：D-xxxx、某段 spec、TODO.md 的条目……（讨论结束时补上）
```

之后的内容随讨论需要写，形式不限：讲解、例子、方案比较、问题清单都可以。决策在「背景」里写一句「讨论见……」，指回讨论稿。
