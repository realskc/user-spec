# 概念

这个目录是 {{项目名}} 的**词典**：给项目里的东西起明确的名字，写清每个名字指什么。

讨论里反复出现的东西，如果没有统一的名字，就会歧义百出；定下名字，能降低认知和沟通的成本。有了明确的概念，作者与 agent 能把事情说清楚，对思考和讲解都有帮助；向作者讲解时，也可以借助概念把具体的例子讲清楚。

其他文档（spec 文档、决策、技术文档）和对话都用这里的名字。一个名字只指一个概念；允许用的别名记在词条里。

## 什么时候定概念

- 讨论里反复出现，却还没有名字；
- 同一个东西有好几种叫法；
- 一个词被用来指不同的东西。

agent 发现这些情况时提醒作者，并给出候选名，由作者定名。

## 规则

- 概念的讨论必须慎重，一点一点确定；
- **概念条目的改变必须由作者提出**；agent 可以做一些修改调整（例如补例子、修措辞，不改变含义）；
- concepts 属于 user spec：修改后同样要在回答末尾用 🟢 向作者汇报。

## 写法

像词典一样：按主题分文件，每个概念一个词条（一个小节），写这些：

- 名字（小节标题），以及允许用的别名；
- 定义：它指什么；
- 例子；
- 不是（辨析）：容易和别的东西混淆时，写它不是什么、区别在哪；
- 代码里的对应：代码里用什么名字（有的话）；
- 含义变过的，注明旧的含义和什么时候变的。
