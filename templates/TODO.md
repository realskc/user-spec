# TODO

待办的**索引**：作者说过以后要做的事、定了方案还没实现的事，都在这里挂一条，链接到详情所在的地方。

- 这里不存内容，只存指针。每一条写三样：要做什么（一句话）、作者说的时间或优先级（原话，如"以后再说""先不做"）、详情的链接。详情照常写在 spec、决策、讨论稿里。
- 只收已有记录的事：作者说的（spec 里写着的），或者决策里定了还没实现的。agent 自己想到的不收；agent 发现的毛病照旧记在技术文档的「已知问题」。
- 是活的文档，做完一条就删一条（做了什么由决策和技术文档记录）。它不是 user spec，不算承重墙，agent 可以随时整理；但每一条的含义来自作者，不自己发挥。
- 作者说还没想好的，记在对应 spec 的「未定」一节，这里不重复列。
- 项目分成几个相对独立的部分时（见 [user-spec/README.md](user-spec/README.md)「一条内容放哪」最后一段），每个部分可以有自己的 TODO.md，写法相同；这里只放全局的条目，并列出各部分 TODO 的链接。某个部分有了第一条待办再建它的 TODO.md。
